# Component documentation

Create a component document when proposing a cohesive component, then update it as implementation and verification proceed. Record its purpose, requirements and approved decisions, actual code locations when they exist, public interfaces, inputs/outputs, dependencies, data flow, errors, authorization, verification, limitations, and an example flow. Explain supporting hooks and functions in the same document when a separate file would add little value.

No product component exists yet. This directory contains no placeholder implementation claims.
